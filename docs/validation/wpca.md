# wpca parity with R

Generated by `scripts/parity_report.py` from the fixtures in `tests/fixtures/wpca/` (R version 4.6.1 (2026-06-24 ucrt), WCluster 1.3.0, x86_64-w64-mingw32, BLAS: Rblas.dll md5 5fe8258e86d8a1a52a6c3db05faa0225, LAPACK 3.12.1, matprod "default", long double: 64-bit significand). Everything up to the matrix handed to eigen() is compared bit for bit, and "yes" there means the same float64 bits, so -0 isn't 0, except that any NaN matches any NaN (`same_values` in `tests/rfixtures.py`). R returns the single number 1 as its scale when corr is FALSE, and the port returns one 1 per column. "centered data" and "eigen input" are the traced locals of R's Wpca, the centered x and the matrix eigen() reads. "scores product" means the port's scores are R's matrix product of R's centered data with the port's own rotation.

LAPACK builds may round sdev, rotation and scores differently, so these are held to R's by a rule, and "yes" in the last column means it passes. Neighbouring eigenvalues closer than 1e-12 times the largest one form a cluster. Only a cluster's subspace is determined and a column's sign isn't, so vectors are compared through their projectors. The port's rotation must be orthonormal within 1e-10. Each of its columns must solve the eigen input, read from its lower triangle as eigen() reads it, for R's eigenvalue with a residual inside a band of 1024 machine epsilons times the largest eigenvalue. Each sdev must be zero or more with its square within that band of R's eigenvalue, and a NaN sdev is allowed only where R's eigenvalue is at most the band. Each cluster's projector must match R's within the larger of 1e-10 and 256 machine epsilons over the cluster's gap to the other eigenvalues, the gap taken relative to the largest eigenvalue. The scores projected onto the cluster must match R's row by row within that tolerance plus 8 p machine epsilons, times the length of the row of centered data. Each check passes only a value shown to be within its bound, so a NaN or an infinity in the port's output fails.

Not reported: `one_iris_first5_petalwidth`, `sum_ld_steps_stops`, `sum_ld_stops` holds only inputs because R stops in eigen() there, and `petalwidth_1d_corr` has one column with corr TRUE, where R's diag() builds an identity and returns the unscaled standard deviation. The port returns 1 to rounding there on purpose.
