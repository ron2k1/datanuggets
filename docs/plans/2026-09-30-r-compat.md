# R compatibility: decision record and plan

Goal: a faithful R-compatible port with an explicit exception list. Every difference from datanugget 1.5.0 and WCluster 1.3.0 is either fixed, measured against a tolerance rule, approved as an exception with a test that pins it, or listed as unresolved.

Branch: `feat/r-compat`, the merge of `feat/wcluster-leaves` (PR #4) and `feat/r-sampler` (PR #5) at 13db6df. Nothing merges until RON2K says so.

Evidence: `r/fixtures_compat.R` records 46 cases into `tests/fixtures/compat` (commit 0b86cf2). Every R behavior quoted below comes from those fixtures or from the earlier fixture groups, never from memory.

Parity means x86-64 R. arm64 R has no long double and gives +NaN for 0/0, so it's a different target.

## The four categories

`docs/compatibility.md` sorts every public behavior into one of these, and the tests name the category they pin.

| Category | Meaning | How a test checks it |
|---|---|---|
| Exact | the port's value has R's bits on every recorded case | `same_bits`, `same_values` or `assert_array_equal` against a fixture |
| Tolerance | equal within a stated rule, and the rule is tested against wrong answers | the eigen rule R1 to R5 (floor 1e-10, C 256, K 1024, tie 1e-12) |
| Approved exception | differs from R by RON2K's decision | a test pins the port's behavior and names the R behavior it replaces |
| Unresolved | differs from R with no decision yet | listed here and in `docs/compatibility.md`, never described as matching |

## Recorded evidence behind the nstart decision

The earlier report both said "reject a non-finite nstart" and "match R's unsplit result". The recorded cases settle it: R never errors in `refine.DN` for a numeric nstart, because the error happens inside `kmeans`, which `refine.DN` catches.

| nstart | `refine.DN` | `stats::kmeans` on the same nugget | Draws before the error |
|---|---|---|---|
| NaN, NA_real_ | unsplit, identical to max.splits=0 | "missing value where TRUE/FALSE needed" | 0 |
| Inf | unsplit | "result would be too long a vector", after the first run | 1 per nugget tried |
| -Inf, 0, -1, 1.5 | unsplit | "argument is of length zero" | 0 |
| 2.5 | splits (20 nuggets to 22) | runs, floor(2.5) = 2 starts | 2 per nugget |
| 25 | splits (20 to 22) | runs | 25 per nugget |
| logical NA | 'nstart must be of class "numeric"' | not reached | 0 |

Messages in every numeric case: "Splitting data nuggets according to max EV...", "split #1", "complete!", "Renumbering the data nuggets...", "completed!". No warnings.

Decision: `refine_dn` accepts any real nstart and matches R's result. The internal `kmeans` raises `KMeansError` with R's message at R's point, so the Inf case consumes R's draws first and fixes K1 (the OverflowError). Python None and bool raise TypeError, the counterpart of R's logical NA error.

## One-column `wpca` with corr=True (held)

`dd` is the weighted standard deviation of each column, `sqrt(diag(x_wcov))`. With corr=True, R's `Wpca` scales the covariance by `diag(1/dd)` on both sides. With one column `1/dd` is a single number, and `diag()` given one number n builds the identity of order floor(n). So:

| Column | dd | floor(1/dd) | R | Independent expectation | Port |
|---|---|---|---|---|---|
| iris Petal.Width | 0.7622 | 1 | sdev = scale = 0.7622376689603465 | 1 | 0.9999999999999999 |
| iris Sepal.Length | 0.8281 | 1 | sdev = scale = 0.8280661279778629 | 1 | 1.0 |
| iris Sepal.Width | 0.4359 | 2 | "non-conformable arguments" | 1 | 1.0 |
| iris Petal.Length | 1.765 | 0 | "non-conformable arguments" | 1 | 0.9999999999999999 |
| faithful eruptions | 1.141 | 0 | "non-conformable arguments" | 1 | 0.9999999999999999 |
| faithful waiting | 13.59 | 0 | "non-conformable arguments" | 1 | 0.9999999999999999 |

The independent expectation is that the correlation matrix of one column is the 1 by 1 matrix 1, so sdev is 1. Two checks agree: R's own `cov2cor()` gives exactly 1.0, and the intended formula written with `diag(1/dd, nrow = 1)` gives 1.0 or 0.9999999999999999 (recorded as `fixed_sdev`). R's sdev when it returns is dd itself, the unscaled standard deviation, which is not a correlation-scale answer.

Options, for RON2K:
- (a) keep the port's 1 (to within an ulp), documented as an exception to R's bug, with a test against `cov2cor` and `fixed_sdev`
- (b) reproduce R: sdev = dd for 0.5 < dd <= 1, raise R's "non-conformable arguments" otherwise

Recommendation: (a), because both independent checks agree with it and R's output there is a side effect of `diag()`'s argument rules. Nothing changes until RON2K picks.
